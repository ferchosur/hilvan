## Recorrido de demostración (verificación de extremo a extremo)

1. Configurar dos perfiles de Claude (A: corporativo con MCP propio; B: personal) y un perfil de Codex (C).
2. Crear una tarea `corporate` que requiere el MCP corporativo → solo A es elegible; B y C aparecen excluidos con su motivo.
3. Ejecutar en A dentro de un worktree. Simular un límite (con el adaptador "fake") → la tarea queda `blocked`.
4. `hilvan handoff` hacia B → una regla requiere aprobación → editar, aprobar y continuar en B. Con la regla gestionada `enforced` activada, el traspaso se bloquea aunque el usuario apruebe.
5. `hilvan review --by C` adjunta la revisión de Codex; `hilvan accept` fusiona y limpia.
6. `events.jsonl` muestra quién recibió qué, con hashes, consumo y estados.

## Fuera del MVP (incremento 2 o posterior)

Lanzador SSH (necesario para el caso de dos máquinas del usuario), ejecución paralela, UI web local, notificaciones, varios repositorios, adaptador ACP, Perplexity (D-004) y monetización (Q-012).
